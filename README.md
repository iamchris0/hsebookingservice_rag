# ВКР (магистратура)
## Разработка и внедрение комплексного сервиса для управления бронированием ассистентов и автоматической поддержки студентов с использованием RAG технологий

---

## Описание проекта

Цель работы — разработать интерактивный веб-сервис для преподавателей, студентов и менеджеров, который:
1) позволяет **бронировать ассистентов** (дисциплины, обр. программы, подтверждения, уведомления, администрирование);
2) предоставляет **автоматическую поддержку пользователям** на базе **RAG (Retrieval-Augmented Generation)**, используя внутреннюю административную/учебную информацию (регламенты, расписания, FAQ, инструкции, документы кафедры и т. п.);
3) включает полноценный production-подобный контур: **Frontend (React)** + **Backend (Node/Express)** + **Python-сервер для RAG** (обучение/индексация/обработка запросов).

---

## Технологический контур (черновой)

- **Frontend:** React, маршрутизация, формы, роли (преподаватель/ассистент/студент/админ)
- **Backend:** Node.js + Express, REST API, аутентификация/авторизация, работа с БД, интеграция с Python-сервисом
- **RAG сервис:** Python (FastAPI/Flask), эмбеддинги, LLM-инференс, мониторинг качества
- **Хранилища:** PostgreSQL (основные сущности), векторное хранилище/индекс
- **DevOps:** Docker / docker-compose, логирование, конфиги окружений

---

## Характер данных и источники знаний для RAG (план)

**Типы данных:**
- Текстовые документы: PDF/DOCX/HTML/MD (регламенты, инструкции, методология, FAQ)
- Полуструктурированные данные: списки дисциплин, правила бронирования, контакты
- Структурированные данные (БД): ассистенты, дисциплины, слоты, бронирования, роли, статусы

**Потенциальные источники:**
- внутренние документы кафедры/вуза, учебные порталы, корпоративные базы знаний
- административные регламенты и инструкции (в том числе локальные нормативные акты)
- накопленные вопросы/ответы для оценки качества RAG

## Верхнеуровневый план работ (этапы)

> Даты примерные и могут уточняться по графику ВКР.  

### Этап 1. Постановка задачи и обзор источников (январь 2026)
- Формализация предметной области: роли, сценарии, ограничения
- Формирование требований к сервису:
  - пользовательские сценарии (бронь, управление слотами, администрирования)
  - требования к RAG: типы запросов, источники знаний, ограничения по приватности
- Обзор литературы и практик:
  - RAG-подходы, chunking, retrieval, reranking
  - метрики качества для retrieval и генерации
  - архитектурные паттерны веб-сервисов и интеграции Python/Node
- Результаты этапа:
  - сформулированные цели/задачи ВКР
  - критерии успешности (KPI) по сервису и по качеству ответов RAG

### Этап 2. Проектирование архитектуры и модели данных (конец января – февраль 2026)
- Проектирование модулей:
  - Frontend (React)
  - Backend API (Node/Express)
  - RAG Python-сервис
  - База данных + векторный индекс
- Проработка интеграции:
  - Связь API между Node и Python (эндпоинты, таймауты, форматы)
  - схема авторизации и разграничение доступа к знаниям
- Проектирование сущностей БД:
  - Users, Roles, Assistants, Teachers, Managers
  - Bookings, BookingStatus, Notifications (опционально)
  - KnowledgeSources, Documents, Chunks, Embeddings (логическая модель)
- Результаты этапа:
  - ER-диаграмма/схема БД
  - описание API и архитектурная схема

### Этап 3. Подготовка данных и пайплайн знаний (февраль – март 2026)
- Сбор и классификация документов для базы знаний
- Парсинг документов и нормализация:
  - извлечение текста, очистка, дедупликация
  - обработка таблиц/метаданных (по возможности)
- Формирование датасетов/корпусов:
  - корпус документов для retrieval
  - набор тестовых вопросов (golden set) для оценки качества
- EDA и анализ качества данных:
  - распределение длин документов/чанков
  - частотные термины, доля мусора, качество извлечения
- Результаты этапа:
  - воспроизводимый пайплайн подготовки данных
  - набор контрольных вопросов и эталонных ожиданий

### Этап 4. Бейзлайн RAG и метрики качества (март 2026)
- Реализация базового RAG:
  - chunking + embeddings + vector search
  - генерация ответа на основе retrieved контекста
- Определение и расчет метрик:
  - retrieval: Recall / Precision
  - генерация: faithfulness/groundedness (через правила/LLM-as-judge)
  - пользовательские метрики: доля ответов “нашёл/не нашёл”, время ответа
- Результаты этапа:
  - baseline-качество, зафиксированное в отчёте
  - список “точек улучшения” (ошибки чанкинга, нехватка контекста, шум)

### Этап 5. Продвинутая RAG-модель и улучшения retrieval (апрель 2026)
- Улучшение retrieval:
  - подбор стратегии chunking (фиксированный/семантический, overlap)
  - reranking (cross-encoder/LLM rerank) при необходимости
  - фильтрация по метаданным и правам доступа (ACL/RBAC)
- Улучшение генерации:
  - шаблоны промпта, структурирование ответа (ссылки на источники, цитаты)
  - механизм отказа/уточнения (“нет данных/уточните запрос”)
  - защита от переобучения: ответы только из контекста, указание источников
- Результаты этапа:
  - сравнение с baseline по метрикам
  - финальный набор настроек/компонентов RAG

### Этап 6. Разработка веб-сервиса бронирования (март – май 2026, параллельно)
- Backend (Node/Express):
  - CRUD сущности (ассистенты, брони)
  - статусы бронирования, бизнес-правила (лимиты по броням)
  - аутентификация/авторизация, роли пользователей
  - интеграция с RAG Python-сервисом (проксирование запросов, логирование)
- Frontend (React):
  - интерфейсы преподавателя (поиск ассистента, создание брони, календарь)
  - интерфейсы ассистента (управление доступностью, подтверждения)
  - админ-панель (управление пользователями/документами знаний — по необходимости)
- Результаты этапа:
  - MVP сервиса с ключевыми сценариями
  - единый репозиторий и инструкции запуска

### Этап 7. Интеграция, тестирование и доработка (май 2026)
- Интеграционные тесты:
  - Node <-> Python, корректность связи API
  - проверка прав доступа к знаниям и данным бронирования
- Нагрузочные/производительные проверки (минимально):
  - время ответа RAG, деградация при росте документов
  - скорость поиска и генерации при типовой нагрузке
- Улучшение UX и стабильности:
  - обработка ошибок, retries, таймауты
  - логирование и мониторинг (минимальный набор)
- Результаты этапа:
  - стабильная демо-версия
  - перечень известных ограничений и план улучшений

### Этап 8. Подготовка отчёта ВКР и демонстрационных материалов (май – июнь 2026)
- Описание архитектуры, обоснование технологий
- Экспериментальная часть:
  - описание данных, baseline vs advanced RAG
  - метрики, результаты, анализ ошибок
- Руководство пользователя и руководство по развертыванию (Docker)
- Подготовка презентации и сценария демонстрации
- Результаты этапа:
  - финальный текст ВКР + приложение (скриншоты, схемы, инструкции)

## Критерии готовности (пример)
- Реализованы ключевые сценарии бронирования + роли пользователей
- RAG отвечает на вопросы по внутренним документам с указанием источников

- Сервис разворачивается одной командой (docker-compose) и демонстрируется стабильно
